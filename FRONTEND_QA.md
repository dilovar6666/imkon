# Проверка Frontend IMKON — 16.10.2026

## Выполнено

- `npm run typecheck` — успешно.
- `npm run build` — успешно после Stitch-редизайна; CSS 31,29 КБ, основной JS 251,59 КБ, отдельно загружаемые модули 19,26/7,68 КБ до gzip.
- `npm run test:browser` — 35 адаптивных проверок: главная, каталог, регистрация, вход, обучение, AI и миссия на 360×800, 390×844, 768×1024, 1440×900 и 1920×1080. Приватные кабинет, работодатель и модерация дополнительно проверены на 390×844 и 1440×900. Снимки в `%TEMP%\imkon-browser-qa`.
- Playwright в Edge: регистрация → подтверждение development-кодом → профиль → резюме с живым предпросмотром → просмотр вакансии → отклик → заявка работодателя. Проверен быстрый поиск с главной. В прогоне с временным администратором тестовой БД: одобрение работодателя → черновик вакансии → отправка на модерацию → публикация → публичный поиск.
- axe-core: 0 автоматических нарушений на главной, каталоге, регистрации, обучении, AI, кабинете соискателя, странице вакансии, кабинете работодателя и админ-панели. Проверены WCAG 2/2.1/2.2 A/AA теги.
- Клавиатура: первая ссылка получает фокус через Tab; мобильное меню и нижняя панель ведут к реальным страницам, панель скрывается при вводе в форму. На мобильном каталоге и кабинете axe-core также не нашёл нарушений. Горизонтальное переполнение мобильных приватных экранов не обнаружено. JS `pageerror` в проверенных сценариях — 0.
- Backend `pytest -q` на отдельной PostgreSQL-базе — 9 passed, 0 failed, 1 предупреждение Starlette/httpx. `GET /admin/users` и `GET /vacancies/{id}` проверены HTTP и тестами.
- `npm audit --audit-level=moderate` — 0 уязвимостей во всех установленных зависимостях.
- Production preview: `npm run test:pwa` — 3 записи в кэше только для статических ресурсов; API и приватные страницы не кэшируются.

## Найдено и исправлено

- В новом макете заголовок каталога занимал слишком много первого экрана; уменьшен, поиск и фильтры подняты ближе к началу страницы. Длинный заголовок вакансии ограничен без обрезания.
- Админ-скриншот сначала снимался во время загрузки и давал ложное впечатление пустой страницы; тест теперь ждёт видимые записи. Предпросмотр сохранённого резюме больше не помечен «не опубликовано».
- Stitch-макеты содержали вымышленные показатели, работодателей и действия; в React они не переносились. Обновлённая композиция использует только реальные API и честные недоступные состояния.
- Обрезание hero и заголовков форм на телефоне; недоступные из мобильного меню ссылки входа.
- CORS локального адреса `127.0.0.1`, не совпадавший с `localhost`.
- Потеря опыта и образования при сохранении резюме; повторная отправка вакансии после перехода в `pending`.
- `GET /admin/users` возвращал 500 при историческом email с зарезервированным доменом в тестовой БД; выходная схема теперь сериализует сохранённую строку, входная EmailStr-валидация сохранена.
- Буквальный HTML в заголовке работодателя; недостаточный контраст текста и акцента — исправлен после axe-проверки.
- Отсутствие прямого чтения вакансии блокировало отклик — добавлен публичный endpoint только для опубликованных и актуальных записей.

## Ограничения проверки

- Только 8 именованных Stitch-экранов получены и визуально изучены; не все 21 экрана проектировались отдельно. `list_screens` MCP возвращал пустой объект, `get_screen` работал по ID.
- На накопленной тестовой БД админ-страница очень длинная: API списков пока не предоставляет пагинацию. Не создавалась выдуманная локальная статистика.
- Приватные страницы не проверялись на всех пяти разрешениях; для них проверены 390×844 и 1440×900. Полный ручной аудит анимаций и screen reader не выполнен.
- Автоматический axe не заменяет ручное тестирование screen reader; оно не выполнено.
- Переключение TG/EN отключено до полной проверенной локализации.
- Полный Kanban, HR, курсы, Gemini, чат и уведомления требуют контрактов из `FRONTEND_API_GAPS.md`.
- После совместимых обновлений и перехода на Tailwind 4 `npm audit` сообщает 0 уязвимостей. Миграция проверена полной сборкой и повторным браузерным прогоном, включая административный сценарий.
- SMTP в production отсутствует; end-to-end подтверждение проверялось с development-кодом на локальной тестовой БД.
